# Web Dashboard Specification

## Purpose

服务端的 React 网页前端：实时展示最新截图的分析进度与结果，提供历史题目列表与详情回顾，以及服务端配置界面（端口、LLM 供应商、并发上限），是解答内容的唯一展示端。

## Requirements

### Requirement: 最新会话实时视图

网页前端 SHALL 默认展示最新 session 的状态与内容：分析中显示进行状态，完成后展示题型、题旨标题（如"选择题——求二叉树最大深度"；题旨为空时仅显示题型）、解答、思路与代码（代码需有语法高亮与格式化展示），并展示本次分析的耗时（从截图到达到分析完成）。前端 MUST 通过服务端推送（SSE）实时更新，无需手动刷新。

#### Scenario: 新截图到达时切换到最新会话

- **WHEN** 用户正在浏览页面时新截图到达
- **THEN** 页面主视图切换到新 session 并显示其进行状态；正在浏览历史记录的用户视图不被强制打断，改以可见提示告知新题到达

#### Scenario: 分析完成实时呈现

- **WHEN** 当前展示的 session 分析完成
- **THEN** 页面在数秒内无刷新呈现完整解答内容（含题旨标题与分析耗时）；编程题的代码块带语法高亮

### Requirement: 历史题目浏览

网页前端 SHALL 提供历史题目侧边列表（时间倒序，摘要含题型、题旨标题与时间戳，题旨为空时仅显示题型），点击任一条目 MUST 在主视图展示该题的完整记录（截图、题型、解答、代码）。浏览历史不打断任何进行中的分析。列表 MUST 支持多选：每条目左侧有选框，并提供全选/全不选操作；选中后 MUST 可对选中题目执行批量删除。批量删除为破坏性操作，执行前 MUST 二次确认并显示选中数量；删除完成后列表与主视图 MUST 即时更新（正在主视图展示的被删题目回到等待态）。选中状态仅保留在浏览端会话内，MUST NOT 写入服务端。

#### Scenario: 回顾历史题目

- **WHEN** 用户点击侧边列表中的一条历史题目
- **THEN** 主视图展示该题的截图原图与完整解答内容（含题旨标题与分析耗时）

#### Scenario: 历史分析在后台完成

- **WHEN** 用户浏览页面期间某个旧 session 在后台完成分析
- **THEN** 侧边列表中该条目状态更新为已完成，当前浏览视图不被打断

#### Scenario: 多选与全选

- **WHEN** 用户勾选若干条目的选框，或点击全选/全不选
- **THEN** 选中集合随之更新，批量操作入口显示当前选中数量

#### Scenario: 批量删除确认执行

- **WHEN** 用户对选中题目发起删除并在确认提示中确认
- **THEN** 服务端删除这些题目，列表即时移除对应条目；若主视图正在展示其中某题，则主视图回到等待新题状态

#### Scenario: 取消删除

- **WHEN** 用户对选中题目发起删除但在确认提示中取消
- **THEN** 不发生任何删除，选中状态保持不变

### Requirement: 答题区宽度调整

网页前端的答题区（会话详情阅读列）SHALL 支持用户拖拽调整宽度：拖动答题区侧缘手柄时列宽按双侧对称方式增减（左右边缘镜像外扩或内收，保持居中），宽度 MUST 钳制在一个最小值与最大值之间（不小于约 600px、不超过约 1280px）。调整后的宽度 MUST 在当前浏览端持久保持（下次打开生效），MUST NOT 写入服务端配置。窄屏布局（侧栏抽屉形态）下 MUST 不出现宽度手柄。

#### Scenario: 对称拖拽调整宽度

- **WHEN** 用户按住答题区侧缘手柄向右拖动一段距离
- **THEN** 答题区左右边缘同时向外扩展相同距离，列宽增大且保持居中，不超过最大宽度

#### Scenario: 宽度持久保持

- **WHEN** 用户调整过答题区宽度后刷新页面或重新打开看板
- **THEN** 答题区以上次调整的宽度呈现

#### Scenario: 窄屏禁用

- **WHEN** 视口宽度处于窄屏（抽屉布局）范围
- **THEN** 不显示宽度手柄，答题区为单列自适应宽度

### Requirement: 服务端配置界面

网页前端 SHALL 提供服务端配置界面， MUST 包含：监听端口、LLM 供应商管理（增删改、协议类型、设为生效）、分析并发上限、分析提示词编辑与编程语言配置。供应商表单 SHALL 提供服务商预设下拉（含 Kimi、DeepSeek、OpenAI、Anthropic 与"其他"，默认选中 Kimi），选择预设时自动预填名称、协议、baseURL 与推荐模型且全部可继续编辑，选择"其他"时不预填。提示词编辑框 MUST 预置当前生效提示词全文（未自定义时为内置默认提示词），并提供恢复默认入口；界面 MUST 提示用户保留提示词中的 JSON 输出结构约定。除端口外的配置修改 MUST 即时生效；端口修改提示需重启服务端。预设下拉仅为输入辅助，MUST NOT 限制用户填写任意供应商参数。

#### Scenario: 修改并发上限

- **WHEN** 用户在配置界面修改最大并发数并保存
- **THEN** 新的上限立即约束后续 session 的调度

#### Scenario: 配置供应商并设为生效

- **WHEN** 用户在配置界面新增供应商并设为生效
- **THEN** 后续新 session 使用该供应商发起分析

#### Scenario: 选择服务商预设

- **WHEN** 用户在新增供应商表单选择预设（如 Kimi）
- **THEN** 名称、协议、baseURL 与推荐模型自动填入且可编辑；切换为"其他"时字段恢复为空

#### Scenario: 编辑分析提示词

- **WHEN** 用户在提示词编辑框修改内容并保存
- **THEN** 后续新 session 使用自定义提示词；点击恢复默认后回退为内置默认提示词

### Requirement: 构建与部署形态

网页前端 SHALL 以 React + 构建工具产出静态资源，由 Node 服务端进程直接托管，局域网内任一设备可通过浏览器访问。前端工程结构 MUST 便于后续迁移到桌面应用壳（Tauri）。

#### Scenario: 局域网访问

- **WHEN** 局域网内另一台设备的浏览器访问服务端地址
- **THEN** 页面正常加载，实时推送、历史列表与配置界面均可用
