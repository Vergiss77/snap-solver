# Delta: web-dashboard

## MODIFIED Requirements

### Requirement: 最新会话实时视图

网页前端 SHALL 默认展示最新 session 的状态与内容：分析中显示进行状态，完成后展示题型、题旨标题（如"选择题——求二叉树最大深度"；题旨为空时仅显示题型）、题目描述（识别出的题目原文，为空时不显示）、解答、思路与代码（代码需有语法高亮与格式化展示），并展示本次分析的耗时（从截图到达到分析完成）。前端 MUST 通过服务端推送（SSE）实时更新，无需手动刷新。

#### Scenario: 新截图到达时切换到最新会话

- **WHEN** 用户正在浏览页面时新截图到达
- **THEN** 页面主视图切换到新 session 并显示其进行状态；正在浏览历史记录的用户视图不被强制打断，改以可见提示告知新题到达

#### Scenario: 分析完成实时呈现

- **WHEN** 当前展示的 session 分析完成
- **THEN** 页面在数秒内无刷新呈现完整解答内容（含题旨标题、题目描述与分析耗时）；编程题的代码块带语法高亮

## ADDED Requirements

### Requirement: Markdown 导出

网页前端 SHALL 支持将题目导出为 Markdown 文件：答题区提供单条导出入口，下载当前题目的 `.md`；历史列表多选后提供批量导出入口，将选中题目按列表顺序合并为单个分节 `.md` 下载。导出内容 MUST 包含题旨标题、题型、题目描述（可为空）、解答、思路与代码（带语言标注），MUST NOT 内嵌截图图片（单文件 Markdown 中图片引用不可达）。导出在浏览器端完成，无需额外服务端接口。

#### Scenario: 单条导出

- **WHEN** 用户在答题区点击导出
- **THEN** 浏览器下载以题旨标题命名的 `.md` 文件，内容为该题的完整结构化文本

#### Scenario: 多选合并导出

- **WHEN** 用户在历史列表选中多题后点击导出
- **THEN** 浏览器下载单个 `.md` 文件，各题按分节依次排列，选中集合与其他批量操作互不干扰

#### Scenario: 题目描述为空时导出

- **WHEN** 导出的记录缺少题目描述（旧记录或解析缺失）
- **THEN** 导出文件中该节省略题目描述部分，其余内容照常
