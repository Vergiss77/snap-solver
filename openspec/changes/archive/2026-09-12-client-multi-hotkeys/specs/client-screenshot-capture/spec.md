# Delta: client-screenshot-capture

## MODIFIED Requirements

### Requirement: 全局快捷键触发截图

客户端 SHALL 在进程运行期间持续监听用户在设置中配置的全部全局快捷键（一个或多个），任一快捷键按下时触发一次截图流程。快捷键 MUST 在操作系统全局生效（无论前台焦点在哪个应用）。客户端 MUST 支持 Windows 与 macOS。每个快捷键的注册相互独立：单个快捷键注册失败 MUST NOT 影响其余快捷键的注册与触发。

#### Scenario: 按下已配置的快捷键

- **WHEN** 客户端进程正在运行且用户按下已配置的任意一个全局快捷键
- **THEN** 客户端在 1 秒内完成一次全屏截图并进入发送流程，前台不出现任何窗口、预览或系统通知

#### Scenario: 快捷键与其他应用冲突

- **WHEN** 已配置的多个快捷键中有一个在操作系统注册失败（被其他应用占用或为系统保留组合）
- **THEN** 设置窗口中该快捷键显示注册失败状态，其余快捷键照常注册并可触发截图

### Requirement: 静默截图

客户端 SHALL 在不产生任何用户可见反馈的前提下捕获当前主屏幕的完整内容，输出为 PNG 编码的图像数据。截图过程 MUST NOT 触发系统截图音效、缩略图预览或屏幕闪烁（操作系统自身的行为除外）。

#### Scenario: 正常截图

- **WHEN** 截图流程被触发且应用已获得所需系统权限
- **THEN** 客户端得到当前主屏幕的完整 PNG 图像，期间屏幕上无任何由客户端引起的视觉变化

#### Scenario: macOS 缺少屏幕录制权限

- **WHEN** 截图流程被触发但 macOS 未授予屏幕录制权限，导致截图结果为空或黑屏
- **THEN** 客户端在设置窗口中显示权限缺失状态与授权引导说明，且不向服务端发送无效图像

### Requirement: 截图发送与离线丢弃

客户端 SHALL 将每张截图通过 HTTP POST 发送到配置的服务端地址，并附带时间戳等元信息。发送 MUST 为异步且不阻塞后续快捷键触发。当服务端不可达（连接失败、超时）时，客户端 MUST 静默丢弃该截图，不缓存、不重试、不提示。

#### Scenario: 服务端在线

- **WHEN** 截图完成且服务端地址可达
- **THEN** 客户端将 PNG 图像与元信息 POST 到服务端接收端点，收到成功响应后结束本次流程

#### Scenario: 服务端离线

- **WHEN** 截图完成但服务端连接失败或请求超时
- **THEN** 客户端静默丢弃该截图，不产生任何用户可见提示，后续快捷键触发不受影响

#### Scenario: 连续触发

- **WHEN** 用户在前一张截图尚未发送完成时再次按下快捷键
- **THEN** 客户端并行处理两次截图流程，互不阻塞、互不丢弃（仅服务端不可达导致的丢弃除外）
