## Purpose

服务端的 HTTP 接收能力：监听可配置端口，接收客户端发送的截图，为每张截图创建独立的分析会话并将图像落盘，同时提供连接检测端点供客户端测试连通性。

## ADDED Requirements

### Requirement: 截图接收端点

服务端 SHALL 暴露一个 HTTP POST 端点，接收 PNG 图像与元信息（客户端时间戳），为每次有效提交创建一个分析会话（session），并 MUST 在触发任何 LLM 分析之前将截图图像持久化到磁盘。接收成功后 MUST 立即返回包含 session 标识的响应，不等待分析完成。

#### Scenario: 正常接收

- **WHEN** 服务端收到包含有效 PNG 图像与元信息的 POST 请求
- **THEN** 服务端创建新 session（状态为待分析）、将图像写入磁盘、返回 2xx 响应与 session ID，并异步启动分析流程

#### Scenario: 无效请求

- **WHEN** POST 请求缺少图像数据或图像无法解码为 PNG
- **THEN** 服务端返回 4xx 错误，不创建 session，不写盘

#### Scenario: 接收期间进程崩溃

- **WHEN** 服务端在图像落盘完成前发生崩溃
- **THEN** 不出现"已返回成功但图像不存在"的 session（落盘先于成功响应）

### Requirement: 可配置监听端口

服务端 SHALL 在启动时监听配置文件中指定的端口（存在默认值），绑定地址 MUST 允许局域网内其他机器访问（非仅 localhost）。

#### Scenario: 默认端口启动

- **WHEN** 配置文件中未指定端口
- **THEN** 服务端监听默认端口，并在启动日志与网页界面中显示实际监听地址

#### Scenario: 端口被占用

- **WHEN** 配置的端口已被其他进程占用
- **THEN** 服务端启动失败并输出明确错误信息，不静默退避到其他端口

### Requirement: 连接检测端点

服务端 SHALL 暴露一个轻量 HTTP GET 健康检查端点，返回服务端版本与运行状态，供客户端"测试连接"功能使用。

#### Scenario: 健康检查

- **WHEN** 客户端向健康检查端点发起 GET 请求
- **THEN** 服务端在 1 秒内返回 2xx 响应，包含服务标识与版本号
